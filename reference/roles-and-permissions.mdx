Every member has exactly one role. Roles are organization-wide; there are no per-project permissions.

| Capability | Viewer | Developer | Admin | Owner |
| --- | :---: | :---: | :---: | :---: |
| View projects, deployments, logs, monitors, incidents | ✓ | ✓ | ✓ | ✓ |
| View non-sensitive environment variables | ✓ | ✓ | ✓ | ✓ |
| Reveal sensitive environment variables | — | ✓ | ✓ | ✓ |
| Trigger, cancel, promote, and roll back deployments | — | ✓ | ✓ | ✓ |
| Create and edit environment variables, domains, flags | — | ✓ | ✓ | ✓ |
| Create and edit monitors; acknowledge and resolve incidents | — | ✓ | ✓ | ✓ |
| Create API keys with scopes up to their own role | — | ✓ | ✓ | ✓ |
| Create, pause, transfer, and delete projects | — | — | ✓ | ✓ |
| Invite, suspend, and remove members; change roles below Admin | — | — | ✓ | ✓ |
| Manage webhooks and integrations | — | — | ✓ | ✓ |
| Edit organization settings and security policy | — | — | ✓ | ✓ |
| View and export the audit log | — | — | ✓ | ✓ |
| Change plan, payment method; view invoices | — | — | — | ✓ |
| Promote members to Admin; transfer ownership | — | — | — | ✓ |
| Delete the organization | — | — | — | ✓ |

## Notes

- There is exactly one **Owner**. Transfer ownership from Settings → General; the previous owner becomes an Admin.
- **API keys** inherit no role. They have only the scopes granted at creation, and a member can't grant a scope beyond their own role.
- **Suspended** members keep their role for record-keeping but can't authenticate.
